### 2. 日志规范化体系 (100%) ✅

#### 2.1 配置logback-spring.xml

**文件:** `src/main/resources/logback-spring.xml`

**日志配置特性:**

**1️⃣ 分级别存储:**
```yaml
logs/fliliy.log         - 所有日志 (保留7天)
logs/fliliy-info.log    - INFO级别 (保留30天)
logs/fliliy-warn.log    - WARN级别 (保留30天)
logs/fliliy-error.log   - ERROR级别 (保留90天)
```

**2️⃣ 滚动策略:**
```yaml
按天滚动: 每天生成新文件
按大小滚动: 单文件最大100MB-200MB
压缩归档: 历史日志自动压缩为.gz
总大小限制: 5GB-10GB
```

**3️⃣ 环境配置:**
```yaml
开发环境(dev):
  - 日志级别: DEBUG
  - 输出: 控制台 + 文件
  - SQL日志: 开启

测试环境(test):
  - 日志级别: INFO
  - 输出: 控制台 + 文件
  - SQL日志: 开启

生产环境(prod):
  - 日志级别: INFO
  - 输出: 文件 (控制台最小化)
  - SQL日志: 关闭
```

**4️⃣ 专项日志:**
```yaml
SQL日志:
  - Hibernate SQL: DEBUG级别
  - 参数绑定: TRACE级别

HikariCP连接池: DEBUG级别
Spring框架: INFO级别
Redis: DEBUG级别
WebSocket: DEBUG级别
```

**日志格式:**
```
控制台: 彩色日志 + 时间 + 级别 + 线程 + 类名 + 消息
文件:   时间 + 级别 + 线程 + 类名 + 消息
```

## 💡 重要提醒

### 错误码使用规范
```java
// ✅ 推荐写法
throw new BusinessException(ErrorCode.USER_NOT_FOUND);

// ✅ 带自定义消息
throw new BusinessException(ErrorCode.SYSTEM_ERROR, "详细错误信息");

// ❌ 不推荐 (除非没有对应的ErrorCode)
throw new RuntimeException("用户不存在");
```

### 日志使用规范
```java
// DEBUG: 详细执行过程
log.debug("Starting to process product: productId={}", productId);

// INFO: 业务操作记录
log.info("User logged in: userId={}, ip={}", userId, ip);

// WARN: 业务异常、限流告警
log.warn("Invalid login attempt: userId={}", userId);

// ERROR: 系统异常、未知错误
log.error("Failed to save product: ", exception);
```

### 参数校验最佳实践
```java
// Controller层: 使用@Valid或@Validated触发校验
@PostMapping("/register")
public ApiResponse<AuthResponse> register(@Valid @RequestBody RegisterRequest request) {
    // 校验失败会被GlobalExceptionHandler捕获
}

// DTO层: 添加校验注解
public class RegisterRequest {
    @NotBlank(message = "手机号不能为空")
    @ValidPhoneNumber
    private String mobile;

    @NotBlank(message = "密码不能为空")
    @Size(min = 6, max = 20, message = "密码长度6-20位")
    private String password;

    @ValidPrice(min = 0.01)
    private Double price;
}
```
