## 一、ActiveTransactions 数据量优化

### 问题描述
聊天列表接口返回所有进行中的交易(PENDING + AGREED状态),理论上可能导致数据量过大。

### 当前评估
- ✅ **正常使用场景**: 每个聊天室1-2个交易,完全可接受
- ✅ **活跃场景**: 5-6个交易也在合理范围内
- ⚠️ **极端场景**: 超过10个交易时才需要优化

### 实施建议
**暂不处理,观察实际使用情况**

**触发条件** (满足任一即需优化):
1. 用户反馈聊天列表加载慢
2. 监控发现平均响应时间 > 500ms
3. 发现有聊天室交易数 > 10个的情况
4. 用户量增长到1000+活跃用户

### 优化方案
参考文档: `/docs/api/ActiveTransactions性能优化方案.md`

**推荐方案**:
- 短期: 限制返回最新N个交易 (N=5-10)
- 长期: 改为懒加载架构
