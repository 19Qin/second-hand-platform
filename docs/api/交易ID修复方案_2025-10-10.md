# 聊天室交易ID修复方案

**日期**: 2025-10-10
**问题**: 聊天室列表响应中transactionId始终为null，无法区分多次交易
**修复人员**: Claude Code

---

## 一、问题分析

### 1.1 原始问题

在测试报告中发现：
- 聊天室列表API返回的`transactionId`字段始终为null
- 同一买卖家可以进行多次交易（不同商品）
- 前端无法区分当前聊天室有哪些进行中的交易
- 每个交易都有独立的交易码，但前端不知道如何获取

### 1.2 核心需求

**用户场景**：
```
买家A 和 卖家B 在同一个聊天室中：
- 第1次交易：购买"小米13 Ultra"（交易码：2621）
- 第2次交易：购买"测试商品"（交易码：4121）

前端需要：
1. 知道当前有哪些进行中的交易
2. 每个交易对应哪个商品
3. 每个交易的状态（PENDING/AGREED）
4. 如果是AGREED状态，买家需要看到交易码
```

### 1.3 设计原则

1. **一个交易 = 一个商品 + 一对买卖家 + 一个交易码**
2. **每次交易都需要双方同意才产生交易码**
3. **前端可以清楚区分不同的交易**
4. **保持向后兼容性**

## 二、解决方案

### 2.1 数据结构设计

**新增字段：activeTransactions**

在`ChatRoomResponse`中添加进行中的交易列表，包含：
- `transactionId`: 交易ID（格式：tx_{id}）
- `productId`: 商品ID
- `productTitle`: 商品标题
- `productImage`: 商品图片
- `productPrice`: 商品价格
- `status`: 交易状态（PENDING或AGREED）
- `role`: 当前用户角色（BUYER或SELLER）
- `transactionCode`: 交易码（**仅AGREED状态且是买家时返回**）
- `codeExpiresAt`: 交易码过期时间
- `requestedAt`: 交易发起时间

## 三、代码修改

### 3.1 修改的文件

1. **ChatRoomResponse.java**
   - 添加`activeTransactions`字段
   - 添加`ActiveTransactionInfo`内部类
   - 标记`transactionId`为`@Deprecated`（保留向后兼容）

2. **TransactionRepository.java**
   - 添加`findActiveByChatRoomId`方法
   - 查询PENDING或AGREED状态的交易

3. **ChatController.java**
   - 注入`TransactionRepository`
   - 修改`convertToChatRoomResponse`方法
   - 填充`activeTransactions`列表

### 3.2 核心代码

```java
// TransactionRepository.java
@Query("SELECT t FROM Transaction t WHERE t.chatRoomId = :chatRoomId AND t.status IN :statuses ORDER BY t.createdAt DESC")
List<Transaction> findActiveByChatRoomId(@Param("chatRoomId") Long chatRoomId,
                                         @Param("statuses") List<Transaction.TransactionStatus> statuses);
```

```java
// ChatController.java - convertToChatRoomResponse
List<Transaction.TransactionStatus> activeStatuses = Arrays.asList(
    Transaction.TransactionStatus.PENDING,
    Transaction.TransactionStatus.AGREED
);

List<Transaction> activeTransactions = transactionRepository.findActiveByChatRoomId(
    chatRoom.getId(), activeStatuses);

for (Transaction transaction : activeTransactions) {
    ActiveTransactionInfo info = new ActiveTransactionInfo();
    info.setTransactionId("tx_" + transaction.getId());
    info.setStatus(transaction.getStatus().name());

    // 确定角色
    String role = currentUserId.equals(transaction.getBuyerId()) ? "BUYER" : "SELLER";
    info.setRole(role);

    // 只有AGREED状态且是买家时，才返回交易码
    if (transaction.getStatus() == Transaction.TransactionStatus.AGREED &&
        currentUserId.equals(transaction.getBuyerId())) {
        info.setTransactionCode(transaction.getTransactionCode());
        info.setCodeExpiresAt(transaction.getCodeExpiresAt());
    }

    activeTransactionInfos.add(info);
}
```

## 四、安全性保证

### 4.1 交易码安全

✅ **交易码只对买家可见**
- 卖家在响应中看不到交易码
- 只有AGREED状态的交易才有交易码
- 买家需要口头或其他方式告知卖家

### 4.2 权限验证

✅ **严格的权限控制**
- 只有聊天室参与者可以查看交易列表
- 每个交易都验证买卖家身份
- 不能响应自己发起的交易申请

### 4.3 状态控制

✅ **状态流转正确**
```
聊天咨询
  ↓
PENDING（买家发起交易申请）
  ↓
  ├─→ AGREED（卖家同意） → 生成交易码 → COMPLETED（卖家输入交易码完成）
  └─→ REJECTED（卖家拒绝）
```

### 5.2 交易卡片渲染

```javascript
function renderTransactionCard(transaction, chatRoom) {
  const card = {
    transactionId: transaction.transactionId,
    product: {
      id: transaction.productId,
      title: transaction.productTitle,
      price: transaction.productPrice,
      image: transaction.productImage
    },
    status: transaction.status,
    role: transaction.role
  };

  if (transaction.status === 'PENDING') {
    if (transaction.role === 'BUYER') {
      // 买家：显示"等待对方响应"
      card.action = '等待卖家响应';
    } else {
      // 卖家：显示"同意/拒绝"按钮
      card.actions = ['同意', '拒绝'];
    }
  } else if (transaction.status === 'AGREED') {
    if (transaction.role === 'BUYER') {
      // 买家：大字显示交易码
      card.transactionCode = transaction.transactionCode;
      card.codeExpiresAt = transaction.codeExpiresAt;
      card.note = '请在线下交易时将此交易码告诉卖家';
    } else {
      // 卖家：显示输入交易码界面
      card.action = '输入买家提供的交易码完成交易';
    }
  }

  return card;
}
```

### 5.3 区分不同交易

```javascript
// 在聊天消息中，通过transactionId匹配对应的交易
function matchTransactionForMessage(message, activeTransactions) {
  if (message.type === 'TRANSACTION_REQUEST' || message.type === 'SYSTEM') {
    const transaction = activeTransactions.find(
      t => t.transactionId === `tx_${message.transactionId}`
    );

    if (transaction) {
      // 找到对应的交易，显示交易详情
      return {
        product: transaction.productTitle,
        status: transaction.status,
        role: transaction.role
      };
    }
  }
  return null;
}
```

## 七、向后兼容性

### 7.1 保留的字段

- `transactionId` (Long): 保留但标记为@Deprecated
- `transactionStatus` (String): 保留但标记为@Deprecated

### 7.2 兼容策略

如果前端还在使用旧字段：
- `transactionId`会返回最新的交易ID
- 不会影响现有功能
- 建议前端尽快迁移到`activeTransactions`
