## 🐛 后端Bug (1个)

### 07. 用户资料 - GET /user/profile

**错误信息**:
```json
{
  "code": 500,
  "message": "获取用户资料失败: class java.util.LinkedHashMap cannot be cast to class com.fliliy.secondhand.dto.response.UserProfileResponse"
}
```

**问题原因**: Redis缓存类型转换错误,`CacheService.getUserProfileCached()` 方法返回了 LinkedHashMap 而非 UserProfileResponse 对象

**位置**: `UserController.java:42`

**建议修复**:
```java
// 修改 CacheService.getUserProfileCached() 方法
// 确保从Redis反序列化时正确转换为UserProfileResponse类型
public UserProfileResponse getUserProfileCached(Long userId) {
    Object cached = redisTemplate.opsForValue().get("user:profile:" + userId);
    if (cached instanceof LinkedHashMap) {
        // 手动转换
        ObjectMapper mapper = new ObjectMapper();
        return mapper.convertValue(cached, UserProfileResponse.class);
    }
    return (UserProfileResponse) cached;
}
```

## 📊 重要发现

### 1. 分页参数

**页码从 1 开始,不是 0**
- ✅ 正确: `?page=1&size=10`
- ❌ 错误: `?page=0&size=10` 会返回 `code: 1001, message: "页码必须大于0"`

### 2. 交易状态查询

**没有独立的 `/transactions/active` 端点**
- ✅ 正确: `GET /transactions?status=PENDING`
- ❌ 错误: `GET /transactions/active` 会返回 500 错误

**可用的状态值**:
- `PENDING` - 待处理
- `AGREED` - 已同意
- `COMPLETED` - 已完成
- `CANCELLED` - 已取消
- `REJECTED` - 已拒绝

### 3. 聊天列表增强字段

聊天列表中新增了 `activeTransactions` 数组:
```json
{
  "activeTransactions": [
    {
      "transactionId": "tx_xxx",
      "productId": 123,
      "status": "PENDING",
      "role": "BUYER"
    }
  ]
}
```

这使得前端可以直接在聊天列表中显示相关交易信息,无需额外请求。

### 4. 商品列表响应结构

商品列表使用标准的分页响应格式:
```json
{
  "content": [],      // 商品数组
  "pagination": {},   // 分页信息
  "filters": null     // 筛选条件
}
```

### 5. ElasticSearch搜索
